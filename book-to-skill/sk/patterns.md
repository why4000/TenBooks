# Patterns

## Pattern 1: 涌现式设计 (Emergent Design)
**When to use**: 需要设计复杂系统，但无法预先设计所有行为。

**How**:
1. 定义简单个体和简单规则。
2. 让个体大量交互。
3. 观察涌现出的整体行为。
4. 调整规则，迭代。

## Pattern 2: 去中心化架构 (Decentralized Architecture)
**When to use**: 系统太复杂，中央控制无法有效管理。

**How**:
1. 将控制权下放到节点。
2. 定义局部交互规则。
3. 让整体秩序从局部涌现。
4. 只设顶层目标，不指定底层方法。

## Pattern 3: 进化搜索 (Evolutionary Search)
**When to use**: 解空间太大，无法穷举或精确求解。

**How**:
1. 定义适应度函数。
2. 随机生成初始种群。
3. 变异+选择+遗传，迭代。
4. 选择适应度最高的解。

## Pattern 4: 造物九律应用 (Nine Laws Application)
**When to use**: 设计或改造一个复杂系统。

**How**: 对照九条法则逐条检查：
1. 存在是否分布式？
2. 控制是否自下而上？
3. 是否有递增收益？
4. 是否模块化？
5. 是否最大化边界？
6. 是否允许错误？
7. 是否避免单一最优？
8. 是否保持不均衡？
9. 改变方式是否能进化？

## Pattern 5: 放手控制 (Letting Go of Control)
**When to use**: 试图完全控制一个复杂系统但失败时。

**How**:
1. 识别哪些部分必须控制（目标、边界）。
2. 放手哪些部分可以自组织（方法、细节）。
3. 建立反馈而非指令。
4. 容忍不可预测性。
